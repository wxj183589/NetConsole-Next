# G2.4 SSH/Telnet 设备连接兼容状态

本阶段基于 G2.3 Terminal Core，未重新建立 SSH 框架，也未改变服务端
`RESTRICTED_READONLY` 命令白名单。

## 已实现

- SSH.NET 现代算法优先；设备登记项可显式启用受控旧算法集合。
- 设备级协议策略支持 `AUTO` / `SSH` / `TELNET`；`AUTO` 只在已登记设备上
  SSH 优先，并且只有明确启用 `allowTelnetFallback` 且 SSH 算法协商失败时
  才尝试 Telnet。Host Key、认证、取消和连接错误不会静默回退 Telnet。
- 设备级 `STRICT` / `AUTO_UPDATE` Host Key 策略。
- 首次信任、指纹变化待确认、连接成功后生效、失败/取消保留旧指纹。
- SQLite schema v8：当前 Host Key、pending/effective/failed 状态、历史事件、
  revision 和设备级策略；重复提交幂等，历史不删除。
- SSH Exec 和 Shell 均记录实际 Host Key 类型、协商算法和 Host Key 决策；Host Key 自动接受事件明确标注
  “不等同于独立身份验证”。Host Key 异常不会回退 Telnet。
- Telnet IAC/login/TTYPE/NAWS 保持原有实现，支持中英文登录提示、设备级 AUTO、
  UTF-8、GB18030 终端文本解码；Web UI 可修改设备兼容策略。

## 安全边界

- 自动信任只对已登记、启用的设备生效；未知设备不会创建 Host Key 记录。
- STRICT 变化拒绝且保留当前指纹。AUTO_UPDATE 只在连接认证和 Shell 建立后
  提交新指纹，并保留旧事件；网络中断、认证失败或取消不会覆盖当前值。
- 旧算法必须按设备显式开启；不会全局降低 SSH 安全策略。
- Telnet 明文连接仅作为设备级显式兼容策略，未登记设备不能使用自动协议选择。
- 当前仍没有真实宁波地铁 10 号线设备证据，因此不宣称真实设备互操作、
  Comware 旧算法兼容或现场编码已通过。
