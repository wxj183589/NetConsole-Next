# NetConsole Next architecture status

Status: `IN_PROGRESS / PARTIAL / REAL_DEVICE_PENDING`. Current connection behavior is summarized below; the later G2/G2.1 phase records retain their historical scope and do not describe the current network SSH implementation.

2026-11-07 connection update: network CLI collection, connection tests, configuration backups, full-device diagnostics and Web Shell use CPython/Netmiko; Linux servers have an independent SSH.NET interactive workflow, and Site Jump Host settings apply to network SSH on demand. Device onboarding is transactional. Saved device/Linux/Jump passwords are SQLite plaintext fields protected by the data-root ACL, with no ordinary-device DPAPI center. The former network SSH.NET transports, custom prompt/paging readers and their wire tests have been removed. The current product ef57213 passed ten local offline candidate gates; [unified architecture acceptance](NETMIKO_UNIFIED_ARCHITECTURE_ACCEPTANCE_20261106.md) records exact commits, commands, evidence and limits.

The Service owns identities, Site, command plans, parsing, SQLite, Raw/Facts/history and AC/AP relations. Netmiko owns network SSH/Telnet authentication, driver preparation, prompts, paging and command reads. A shared limit of 16 worker processes covers collection, tests, network terminals and Jump probes. Recovery is bounded and only applies to an exact read-only command whose connection was lost before sending; unknown post-send outcomes and interactive input are not replayed. FIT-AP stays AC-managed. AC optional resources expose command evidence; AP group names remain source-AC-scoped candidates. Three backup kinds separate running/saved content from startup file pointers. Full diagnostics reuse the same transport and sealed TXT/ZIP evidence, with a 540-second read deadline and 4 MiB output limit. These boundaries do not establish field-device compatibility or full product completion.

## Historical G2/G2.1 design record

The sections below preserve the earlier schema, Exec-channel, SSH.NET, single-command task and CI evidence for audit. Those retired network paths are not runtime fallback paths. Current network behavior and remaining gaps are authoritative in the linked current acceptance and integration documents.

## Current process boundary

```text
NetConsole.Next.Service
  ├─ Windows Service host adapter / generic host lifecycle
  ├─ loopback health endpoint and bearer-protected local management API
  ├─ UDP Syslog receiver → packet/byte-bounded channel → batched Raw NDJSON segment writer
  ├─ SQLite v7 catalog, incremental startup reconciliation, integrity audit and explicit issue disposition
  ├─ process, queue, collection and disk-free monitoring
  ├─ bounded, count-retained local rolling logs
  └─ bounded persisted scheduler with simulated sessions and opt-in H3C SSH read-only collection
  ├─ optional Terminal Session Manager: network-device SSH/Telnet via Netmiko, Linux-server SSH.NET ShellStream and local serial transports
  ├─ loopback WebSocket gateway with one-time terminal tickets and bounded output buffering
  └─ bounded segmented JSONL terminal recordings plus SQLite session/event/history metadata
  └─ CPython/Netmiko worker for production network-device CLI collection

NetConsole.Next.LocalManager
  └─ local CLI for service control and protected API token rotation

NetConsole.Next.Credentials
  └─ local API token file and compatibility credential maintenance helpers
```

The Service has no UI dependency. Web binds only to loopback (`127.0.0.1`, `localhost` or `::1`); wildcard, LAN and other non-loopback HTTP bindings are rejected, and `NETCONSOLE_NEXT_WEB_LAN=1` cannot bypass this gate. Every `/api/system/*` route accepts the existing bearer token for LocalManager automation or a Web PR-1 Cookie session; Cookie writes require same-origin Origin and CSRF validation. The data root contains the local API token; Linux token mode is `0600`, Windows inherits an ACL restricted to SYSTEM, Administrators and the service SID. The Local Manager can display/rotate the token. `schema_v9` seeds hashed `admin`/`superadmin` users and persists unique instance identity. No CORS policy is enabled. UDP remote binding requires explicit opt-in. A future remote Web mode requires a separate TLS-enforced security design. The Local Manager is a local process and does not own the Service lifetime.

Terminal endpoints are opt-in (`NETCONSOLE_NEXT_TERMINAL_ENABLED=1`). Session creation accepts a registered H3C profile for network-device SSH/Telnet, a registered Linux server for Linux SSH, or a currently enumerated local COM port for Serial. Network-device SSH/Telnet uses the Netmiko worker; Linux SSH uses the separate SSH.NET ShellStream transport. The network-device mode is server-enforced `RESTRICTED_READONLY`; raw WebSocket bytes and arbitrary host/port targets are not accepted. A short-lived one-time ticket is issued through the bearer-protected local API and consumed exactly once by the WebSocket stream.

Terminal history is separate from live transport sessions. History queries are paged and filter by registered target, protocol, time, state, integrity and recorded command keyword. Replay reads the controlled recording root through bounded pages and never creates a transport or ticket. Export is loopback/Bearer protected, streams TXT/JSONL/escaped HTML/manifest data, and records an audit row with verification status. Until a real authenticated operator model exists, history and export identity is `UNATTRIBUTED`.

## Storage boundary

The new data root is independent from the existing NetConsole product. It contains `catalog.db`, `raw/`, a root marker, a recovery-in-progress marker during reconciliation, and (when recovery repairs a corrupt tail) `recovery-evidence/`. `catalog.db` is the metadata authority; Raw bytes remain files. The damaged tail evidence is not served by an API. See [DATABASE_DESIGN.md](DATABASE_DESIGN.md).

Startup still walks the Raw directory and checks indexed file metadata. It skips file contents and catalog writes only when a finalized row has a checksum and its size/last-write timestamp match the checkpoint captured after full verification. Older rows without checkpoints are read and hashed once. A low-priority hosted maintenance task starts after ten minutes and fully audits at most one finalized file per minute. This metadata shortcut assumes ordinary filesystem timestamp behavior; it does not detect a same-size rewrite that also preserves the timestamp until that full audit reaches the file.

Raw recovery distinguishes a historical segment issue from a critical SQLite, Raw-root, or Raw-write failure. Health reports `HEALTHY`, `DEGRADED`, or `FAULTED`; degradation causes are tracked independently so resolving Raw integrity cannot clear interrupted-task, interrupted-recovery, or maintenance-runtime warnings. An interrupted recovery keeps that process `DEGRADED` after replay completes; a clean subsequent process start clears this transient cause. Unresolved integrity audits and task runs interrupted during the previous process lifetime keep health at `DEGRADED`. A later full integrity check can record `RESOLVED_VERIFIED`, including a later successful retry of a transient `MAINTENANCE_FAILED` audit. An operator may record `QUARANTINED` for unchanged, hash-verified bytes; this is a logical Catalog disposition only. It does not move or delete Raw bytes or recovery evidence. If bytes change later, a new audit is recorded and health degrades again. Critical storage failures keep the loopback health endpoint available when the host can start, but collection admission is disabled. A runtime Raw/SQLite write failure stops UDP admission, retains `.open` or finalized evidence where possible, and reports `FAULTED`.

## Collection boundary

Syslog requests a 4 MiB UDP receive buffer and records the OS-reported effective value. One `ReceiveAsync` reader feeds a channel bounded by 8,192 packets and 32 MiB of payload. The Raw writer stages NDJSON without an intermediate Base64 string and starts a sync batch when it reaches 256 records, 256 KiB, 100 ms age, or a 4 MiB segment boundary. The 100 ms value schedules a flush; slow storage can make completion take longer. Each completed batch still calls `Flush(true)`; SQLite retains `synchronous=FULL`. Normal stop drains and seals the current segment. This does not guarantee zero loss on process kill or power failure: packets still in the kernel, queued packets and staged records not yet synchronized may be lost; an `.open` prefix that reached storage is preserved for recovery. The packet count limit was raised from 2,048 after measurements showed segment-seal stalls up to about 1.2 seconds while the separate 32 MiB payload bound was mostly unused. Paired and traced runs are recorded in [PERFORMANCE_BASELINE.md](PERFORMANCE_BASELINE.md); they are not a sustainable industrial-host throughput claim.

`BoundedCollectionScheduler` provides finite admission, concurrency, per-run timeout/cancel and an `IDeviceSession` lifecycle. Simulated command echo remains available to tests. H3C collection is opt-in with `NETCONSOLE_NEXT_H3C_ENABLED=1` (default off). It supports the allowlisted read-only set `display version`, `display interface brief`, `display device`, the H3C WLAN AP/Radio commands, LLDP list/verbose and transceiver diagnosis; task definitions persist one command per run. The Phase 9 ZTE parser and command policy are offline-only and are not a runtime ZTE collection/API/GUI contract. SSH.NET 2026.0.0 uses a SHA-256 host-key pin and an explicit modern key-exchange, cipher, MAC and host-key allowlist. `SshCommand` Exec Channel remains in use; interactive Shell is not enabled because no field device established that it is needed. SSH.NET's stdout/stderr `PipeStream` is non-seekable, so command output is actively drained rather than checked through `Length`; combined stdout/stderr has a 256 KiB cap. A limit breach aborts the session; bounded decoded stdout is retained as `PARTIAL` when present. Pagination and nonzero Exec results also retain available bounded stdout as `PARTIAL` and never mark it complete. Connection setup is timed until the pinned host key callback completes; authentication is timed from that callback until `ConnectAsync` returns. These callback-based measurements split the phases exposed by SSH.NET, not packet-level timing. No automatic retry is performed. Failures expose coarse categories, never credentials, command output or unnecessary device identity.

Production network-device CLI collection and network-device interactive Web Shell use the CPython/Netmiko worker described in [NETMIKO_INTEGRATION.md](NETMIKO_INTEGRATION.md). The .NET service owns the device profile credential, worker process lifetime and HostKey Catalog decision; Netmiko owns SSH/Telnet connection and command interaction. The profile password is stored on the device record and read by profile ID, while HostKey state remains separate. The current field is ACL-protected local storage, not a database encryption or remote secret-manager claim. Development-only environment credentials remain available behind `NETCONSOLE_NEXT_H3C_DEV_ENV_CREDENTIALS=1`. Passwords never enter task requests, Raw, logs, health responses or task history. The legacy SSH.NET network-device transport remains only for explicit synthetic wire tests. Linux-server interactive terminals are a separate registered-server workflow using SSH.NET ShellStream; this does not create a second network-device CLI connection stack. Capture, parse and task result status remain distinct: capture is `COMPLETE/PARTIAL`, parse is `PARSED/EMPTY/UNRECOGNIZED/PARTIAL`, and task outcome is `SUCCEEDED/FAILED/TIMED_OUT/CANCELLED/INTERRUPTED`. A partial capture cannot succeed. A complete but unknown Comware format can have successful capture and `UNRECOGNIZED` parse status.

The local management API is a loopback-only convenience boundary protected by a high-entropy bearer token and exact loopback Host validation; health is read-only and unauthenticated. A future remote management mode needs a separate security design with authenticated identities, TLS, strict Origin/source validation, CSRF protection and role-scoped authorization before any listener expansion. The local token is not a remote-user identity system.

After a command response is available, the writer synchronizes and seals a one-record Base64 NDJSON segment under `raw/h3c/<profile-id>/...`. It stores output and segment SHA-256, capture status and task-run ID; catalog-relative paths use forward slashes on every OS. One SQLite transaction inserts `task_run_raw_outputs` and transitions the run terminal state. If the process exits after Raw sealing but before that transaction, startup validates the file and idempotently rebuilds the missing manifest while retaining the run's `INTERRUPTED` state. Recovery preserves legacy catalog path strings when updating existing rows and compares path separators according to the host OS. Windows slash aliases for one physical segment collapse to one recovery candidate and one health count; distinct Raw segments for the same run are rejected. All recovered manifests commit in one transaction, so an ambiguous or invalid candidate set leaves the result table unchanged and preserves Raw evidence. Schema v5 adds this relationship/status. Golden fixtures plus a test-only Paramiko server exercise SSH.NET's actual wire negotiation, password auth, pinned and rejected host keys, Exec response, silent-peer cancellation, abrupt reset and two concurrent sessions on Linux and Windows CI. These synthetic responses do not verify real Comware SSH/CLI behavior or device output variants.

## Persistent task model and limits

Service, Syslog and H3C source lifecycle rows, plus simulated/H3C `Task Definition` and `Task Run` rows, are persisted in SQLite. Runs use a bounded queue and record queue/start/deadline/end times, state, definition and failure reason. Scheduler active capacity remains occupied until the terminal SQLite transition completes; for H3C it also remains active until Raw and its manifest are durable. Rejected state transitions and database errors are surfaced instead of silently treating an in-memory result as durable. On startup, queued/connecting/running runs become `INTERRUPTED`; `NEVER` is the only restart policy and requires an explicit retry. There is no distributed scheduler, automatic retry, SNMP driver, Syslog multi-source API, MR collection, or task-center UI.

Resource snapshots include CPU, working set, thread/Windows handle count, and data-volume free space. UDP health includes received/admitted/application-drop/flushed counts, queue packet/byte high-watermarks, requested/effective socket buffer values and rolling Raw sync/seal/SQLite-registration latency. H3C health metrics include active sessions, combined connect/auth duration for compatibility, separate connection/key-exchange setup and authentication durations, command, Raw sync/seal, atomic SQLite commit and task duration totals, and sanitized failure-category counts. SQLite uses WAL, a 5-second busy timeout and `synchronous=FULL`; the file logger rotates at 5 MiB and retains at most 14 service log files. The Windows installer assigns a dedicated virtual service account with read/execute access to publish files and modify access only to the isolated data root; that root ACL excludes ordinary local users. Current G2.1 PR #11 Windows Server 2025 CI passed the publish/install and actual SCM lifecycle, DPAPI, token rotation and tighter ACL checks (Actions run `39638777555`). Schema v3 adds integrity dispositions, v4 adds H3C profiles/output manifests, v5 adds Raw/task linkage and capture/parse statuses. Managed backup/restore and explicit WAL checkpoint policy are not implemented. Windows 10/11 target behavior, old Windows, low-spec hosts and real devices remain pending.
