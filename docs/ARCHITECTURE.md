# NetConsole Next architecture status

Status: `IN_PROGRESS`. This describes code present on the G2.1 development line; it is not a production deployment claim.

## Current process boundary

```text
NetConsole.Next.Service
  ├─ Windows Service host adapter / generic host lifecycle
  ├─ loopback health endpoint and bearer-protected local management API
  ├─ UDP Syslog receiver → packet/byte-bounded channel → batched Raw NDJSON segment writer
  ├─ SQLite v5 catalog, incremental startup reconciliation, integrity audit and explicit issue disposition
  ├─ process, queue, collection and disk-free monitoring
  ├─ bounded, count-retained local rolling logs
  └─ bounded persisted scheduler with simulated sessions and opt-in H3C SSH read-only collection

NetConsole.Next.LocalManager
  └─ local CLI for service control, protected API token rotation and Windows DPAPI credential maintenance

NetConsole.Next.Credentials
  └─ local API token file and Windows-only DPAPI machine-scope credential vault
```

The Service has no UI dependency. The Web endpoint binds to `127.0.0.1`; every `/api/system/*` route requires a bearer token except read-only health, and all require a loopback remote address plus `127.0.0.1:<port>` or `localhost:<port>` Host. The data root contains the token; Linux token mode is `0600`, Windows inherits an ACL restricted to SYSTEM, Administrators and the service SID. The Local Manager can display/rotate the token. No CORS policy is enabled. Remote Web authentication, CSRF, user roles and audit identity are not implemented. UDP remote binding requires explicit opt-in. The Local Manager is a local process and does not own the Service lifetime.

## Storage boundary

The new data root is independent from the existing NetConsole product. It contains `catalog.db`, `raw/`, a root marker, a recovery-in-progress marker during reconciliation, and (when recovery repairs a corrupt tail) `recovery-evidence/`. `catalog.db` is the metadata authority; Raw bytes remain files. The damaged tail evidence is not served by an API. See [DATABASE_DESIGN.md](DATABASE_DESIGN.md).

Startup still walks the Raw directory and checks indexed file metadata. It skips file contents and catalog writes only when a finalized row has a checksum and its size/last-write timestamp match the checkpoint captured after full verification. Older rows without checkpoints are read and hashed once. A low-priority hosted maintenance task starts after ten minutes and fully audits at most one finalized file per minute. This metadata shortcut assumes ordinary filesystem timestamp behavior; it does not detect a same-size rewrite that also preserves the timestamp until that full audit reaches the file.

Raw recovery distinguishes a historical segment issue from a critical SQLite, Raw-root, or Raw-write failure. Health reports `HEALTHY`, `DEGRADED`, or `FAULTED`; degradation causes are tracked independently so resolving Raw integrity cannot clear interrupted-task, interrupted-recovery, or maintenance-runtime warnings. An interrupted recovery keeps that process `DEGRADED` after replay completes; a clean subsequent process start clears this transient cause. Unresolved integrity audits and task runs interrupted during the previous process lifetime keep health at `DEGRADED`. A later full integrity check can record `RESOLVED_VERIFIED`, including a later successful retry of a transient `MAINTENANCE_FAILED` audit. An operator may record `QUARANTINED` for unchanged, hash-verified bytes; this is a logical Catalog disposition only. It does not move or delete Raw bytes or recovery evidence. If bytes change later, a new audit is recorded and health degrades again. Critical storage failures keep the loopback health endpoint available when the host can start, but collection admission is disabled. A runtime Raw/SQLite write failure stops UDP admission, retains `.open` or finalized evidence where possible, and reports `FAULTED`.

## Collection boundary

Syslog requests a 4 MiB UDP receive buffer and records the OS-reported effective value. One `ReceiveAsync` reader feeds a channel bounded by 8,192 packets and 32 MiB of payload. The Raw writer stages NDJSON without an intermediate Base64 string and starts a sync batch when it reaches 256 records, 256 KiB, 100 ms age, or a 4 MiB segment boundary. The 100 ms value schedules a flush; slow storage can make completion take longer. Each completed batch still calls `Flush(true)`; SQLite retains `synchronous=FULL`. Normal stop drains and seals the current segment. This does not guarantee zero loss on process kill or power failure: packets still in the kernel, queued packets and staged records not yet synchronized may be lost; an `.open` prefix that reached storage is preserved for recovery. The packet count limit was raised from 2,048 after measurements showed segment-seal stalls up to about 1.2 seconds while the separate 32 MiB payload bound was mostly unused. Paired and traced runs are recorded in [PERFORMANCE_BASELINE.md](PERFORMANCE_BASELINE.md); they are not a sustainable industrial-host throughput claim.

`BoundedCollectionScheduler` provides finite admission, concurrency, per-run timeout/cancel and an `IDeviceSession` lifecycle. Simulated command echo remains available to tests. H3C collection is opt-in with `NETCONSOLE_NEXT_H3C_ENABLED=1` (default off). It supports only `display version` and `display interface brief`; task definitions persist one command per run. SSH.NET 2026.0.0 uses a SHA-256 host-key pin and an explicit modern key-exchange, cipher, MAC and host-key allowlist. `SshCommand` Exec Channel remains in use; interactive Shell is not enabled because no field device established that it is needed. SSH.NET's stdout/stderr `PipeStream` is non-seekable, so command output is actively drained rather than checked through `Length`; combined stdout/stderr has a 256 KiB cap. A limit breach aborts the session; bounded decoded stdout is retained as `PARTIAL` when present. Pagination and nonzero Exec results also retain available bounded stdout as `PARTIAL` and never mark it complete. Connection setup is timed until the pinned host key callback completes; authentication is timed from that callback until `ConnectAsync` returns. These callback-based measurements split the phases exposed by SSH.NET, not packet-level timing. No automatic retry is performed. Failures expose coarse categories, never credentials, command output or unnecessary device identity.

Windows resolves a credential reference from `<data-root>/credentials/h3c-credentials.v1.json`; values are protected by DPAPI `LocalMachine`, and the Windows installer limits the inherited data-root ACL to SYSTEM, Administrators and the service SID. Local Manager supports set/update/revoke. This is machine-level DPAPI plus filesystem ACL, not a remote secret manager or per-user DPAPI boundary. On Linux/Kylin, the provider returns unavailable; environment credentials require both Development host environment and `NETCONSOLE_NEXT_H3C_DEV_ENV_CREDENTIALS=1`. Passwords never enter SQLite task requests, profiles, logs, health responses or task history. SSH.NET decodes command output as strict UTF-8; Raw stores **the SSH.NET-decoded UTF-8 command output**, not SSH wire bytes. Capture, parse and task result status remain distinct: capture is `COMPLETE/PARTIAL`, parse is `PARSED/EMPTY/UNRECOGNIZED/PARTIAL`, and task outcome is `SUCCEEDED/FAILED/TIMED_OUT/CANCELLED/INTERRUPTED`. A partial capture cannot succeed. A complete but unknown Comware format can have successful capture and `UNRECOGNIZED` parse status.

The local management API is a loopback-only convenience boundary protected by a high-entropy bearer token and exact loopback Host validation; health is read-only and unauthenticated. A future remote management mode needs a separate security design with authenticated identities, TLS, strict Origin/source validation, CSRF protection and role-scoped authorization before any listener expansion. The local token is not a remote-user identity system.

After a command response is available, the writer synchronizes and seals a one-record Base64 NDJSON segment under `raw/h3c/<profile-id>/...`. It stores output and segment SHA-256, capture status and task-run ID. One SQLite transaction inserts `task_run_raw_outputs` and transitions the run terminal state. If the process exits after Raw sealing but before that transaction, startup validates the file and idempotently rebuilds the missing manifest while retaining the run's `INTERRUPTED` state. Schema v5 adds this relationship/status. Golden fixtures plus a test-only Paramiko server exercise SSH.NET's actual wire negotiation, password auth, pinned and rejected host keys, Exec response, silent-peer cancellation, abrupt reset and two concurrent sessions on Linux and Windows CI. These synthetic responses do not verify real Comware SSH/CLI behavior or device output variants.

## Persistent task model and limits

Service, Syslog and H3C source lifecycle rows, plus simulated/H3C `Task Definition` and `Task Run` rows, are persisted in SQLite. Runs use a bounded queue and record queue/start/deadline/end times, state, definition and failure reason. Scheduler active capacity remains occupied until the terminal SQLite transition completes; for H3C it also remains active until Raw and its manifest are durable. Rejected state transitions and database errors are surfaced instead of silently treating an in-memory result as durable. On startup, queued/connecting/running runs become `INTERRUPTED`; `NEVER` is the only restart policy and requires an explicit retry. There is no distributed scheduler, automatic retry, SNMP driver, Syslog multi-source API, MR collection, or task-center UI.

Resource snapshots include CPU, working set, thread/Windows handle count, and data-volume free space. UDP health includes received/admitted/application-drop/flushed counts, queue packet/byte high-watermarks, requested/effective socket buffer values and rolling Raw sync/seal/SQLite-registration latency. H3C health metrics include active sessions, connection/key-exchange setup, authentication, command, Raw sync/seal, atomic SQLite commit and task duration totals, and sanitized failure-category counts. SQLite uses WAL, a 5-second busy timeout and `synchronous=FULL`; the file logger rotates at 5 MiB and retains at most 14 service log files. The Windows installer assigns a dedicated virtual service account with read/execute access to publish files and modify access only to the isolated data root; that root ACL excludes ordinary local users. Windows Server 2025 CI on PR #10 exercised actual SCM lifecycle. G2.1 adds an extended Windows workflow for DPAPI, token rotation and the tighter ACL; its result belongs to the current PR CI. Schema v3 adds integrity dispositions, v4 adds H3C profiles/output manifests, v5 adds Raw/task linkage and capture/parse statuses. Managed backup/restore and explicit WAL checkpoint policy are not implemented. Windows 10/11 target behavior, old Windows, low-spec hosts and real devices remain pending.
