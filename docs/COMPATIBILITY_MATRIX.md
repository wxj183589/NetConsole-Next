# Runtime and OS compatibility matrix

Current Service and Local Manager target `net10.0`. Build success on a current runner is not runtime support for an older Windows release.

The release target remains Windows x64. Do not advertise any target OS based on compilation. Microsoft's [.NET on Windows support table](https://learn.microsoft.com/en-us/dotnet/core/install/windows) lists Windows Server 2012/2012 R2 for .NET 10 x64, but their final ESU year ended October 14, 2026 (see [Server 2012 lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/windows-server-2012) and [Server 2012 R2 lifecycle](https://learn.microsoft.com/en-us/lifecycle/products/windows-server-2012-r2)); this makes them an unsupported security baseline for a new deployment absent a separately approved isolation/exception. Native dependencies and Service/SCM behavior are untested. Windows 8/8.1 requires an OS upgrade for a supported modern .NET path. Minimal POC: disposable VMs for Windows 10 LTSC/Enterprise and Windows 11; publish and install current EXEs, verify runtime/native dependencies, ProgramData ACL, start/stop/restart/crash recovery and uninstall retention. Server 2012/R2 tests, if needed for migration planning, must use isolated, non-production VMs and must not be described as a supported production target. Any Windows 8.1-only customer case needs an OS migration decision; do not transplant the current `net10.0` project onto an unsupported runtime.

H3C SSH currently targets the .NET 10.0 `SSH.NET` package asset. Windows Server 2025 compilation, synthetic tests, and Service publish/SCM lifecycle passed in PR #10 CI. Windows 10/11, Server 2012/R2 and Windows 8/8.1 have no G2 SSH verification. Older Comware SSH algorithm support may be incompatible with the security allowlist and must be assessed on an isolated, authorized device before any field use.
