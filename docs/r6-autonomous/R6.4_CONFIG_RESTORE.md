# R6.4 Config Restore

State: **PARTIAL / fail-closed**.

Schema v25 persists restore intent without storing the confirmation token or configuration body. Confirmation uses a serializable transaction to move `PREVIEWED` to `CLAIMED`, records an attempt id, enforces one active operation per target profile and invokes no automatic replay. `EXECUTING` and other in-flight states become `REQUIRES_REVIEW` during service initialization. Cancellations and unknown Writer exceptions also require review.

The default `DisabledConfigRestoreWriter` remains registered. A future Writer must add pre-write recapture, compatibility checks, idempotency handling, post-write fact verification and rollback verification before it can be enabled.

The read-only `GET /api/system/config-backups/restore/operations/{id}` endpoint exposes durable state to the authorized actor and Site scope without returning the confirmation token or token hash.

An unresolved `REQUIRES_REVIEW` operation remains mutually exclusive for the target until an operator reviews it. The default `DisabledConfigRestoreWriter` is still fail-closed; its attempted boundary is recorded for review and no device write is claimed.
