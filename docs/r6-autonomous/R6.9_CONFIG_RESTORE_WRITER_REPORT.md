# R6.9 Configuration Backup and Controlled Writer

Status: **PARTIAL**. Complete private configuration backup and a reversible interface-description Writer are implemented. Whole-device configuration replacement is not implemented or accepted.

## Delivered behavior

- Existing general snapshots remain sanitized and `restorable=false`. Downloads and diffs verify byte count and SHA-256 on the same opened file stream, including same-length tampering rejection.
- The simulator-only complete-backup API stores original bytes, a separate sanitized view, and metadata under `backup/config-complete/<profile>`. Original bytes never enter Facts or public Raw. The general file manager protects this directory from listing, direct download, previews and archives. The dedicated view API returns sanitized text only.
- Metadata binds Device ID, profile, Site, endpoint/protocol, model, Comware version, capture time, task ID, original/public sizes and hashes. Each read verifies complete Comware framing, both hashes and the sanitized projection. Changed inventory identity is not advertised as restorable. Configuration revision advances independently from manifest format version.
- `restorable=true` identifies a complete verified original usable as the controlled Writer baseline. It does **not** mean a whole-device restore endpoint exists or has passed acceptance.
- Only four authorized simulator endpoints with exact SSH/Telnet ports are admitted. SUPERADMIN, unique enabled inventory association, frozen Device/Site/endpoint identity, current authority checks, direct connection and endpoint serialization are required.
- Netmiko accepts a validated interface and ASCII description or `null` (undo description). The worker accepts no arbitrary command list, save/reboot operation, VLAN change or whole configuration payload; it repeats endpoint/driver/direct-connection/input validation.
- The service compares a complete live capture and device version against the selected baseline. A durable `REQUIRES_REVIEW` record and audit precede the uncertain write boundary. `VERIFIED` requires actual full reread, the desired description and no changes outside that description.
- An uncertain write or mismatching reread triggers a new bounded recovery session. `ROLLBACK_VERIFIED` requires original-description restoration and canonical equality of the complete configuration; otherwise the operation records `ROLLBACK_FAILED`. HTTP cancellation after Writer does not cancel recovery. Process interruption leaves the uncertain record for review.
- Predictable credential, authentication, host-key, timeout, protocol, transport and storage errors use fixed safe codes. Error details do not expose secrets or device output.
