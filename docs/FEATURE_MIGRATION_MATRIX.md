# Feature migration matrix

Updated 2026-11-09 for R7.8, committed-source baseline `5500014`, branch `codex-A/netconsole-next-r3-dual-ac`. This replaces the 2026-10-19 snapshot. Network-device collection and terminals now use the existing CPython/Netmiko worker; Linux server terminals retain their separate SSH.NET transport. The old two-command collector description is obsolete.

Original references were recorded from `wxj183589/NetConsole` main `d457f6d`; later mappings are in [the R7.1 parity matrix](r6-feature-parity/ORIGINAL_TO_NEXT_FEATURE_MATRIX.md). This audit inspected Next source and existing reports only, without revisiting the original repository, copying data, connecting to devices or rerunning test suites. A listed test is an audit entry point, not a fresh execution result.

Statuses apply to the named capability: `EXISTING` means reused existing Next capability; `IMPLEMENTED` means the bounded capability has source/API/UI and tests; `PARTIAL` means larger business parity remains incomplete; `MISSING` means no corresponding product implementation was identified; `BLOCKED` means a required external capability or acceptance prerequisite is unresolved. Implementation status is separate from field acceptance.
