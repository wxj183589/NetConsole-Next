# ADR-0001: NetConsole Next 技术与产品方向

状态：产品方向已确认；P0 为技术原型，生产技术和旧系统兼容尚未验收。

1. NetConsole-Next 是未来主力仓库。现有 NetConsole 继续修复、必要优化、现场维护。
2. 主场景为 Windows x64（Intel/AMD）低配置工业主机，7x24 实时数据采集。
3. 系统稳定性与真实 Raw 数据优先于工具集、分析和报表。
4. 后台采集服务与界面分离；Web 为唯一主业务 UI，桌面仅保留可选 Local Manager（停止/启动、打开目录、文件管理）。
5. SQLite 主库 + 原始文件段使用全新模型，**不兼容、也不访问**旧版数据库。
6. Core 模块化单体，按需启用业务组件；文件协议服务（HTTP/FTPS/FTP/TFTP/WebDAV/SSH-SFTP）均默认禁用。
7. 本机 SSH 设备采集客户端与可选 SSH 文件服务器互不依赖。
8. 优先用 C# 验证；当前 .NET 10 原型**不代表支持 Windows 8**。Windows 8/8.1 和 Server2012/R2 必须单独验证或选择适当兼容宿主。
9. 不复制 iMC/U-Center 重型集群方案：仅参考基础平台与业务组件划分；参考 Telegraf 的有界采集/批处理和 Fluent Bit 的缓冲背压。

## 严格限制

旧仓库生产数据不共用、不迁移；本期不建设 Agent Controller、不做大规模业务迁移、不开放未认证远程 Web。

## P2 终端边界

内置终端仍属于 Headless Core Service 的可选工具组件。首期只接受已登记设备或本机当前枚举的串口，服务器端固定使用 `RESTRICTED_READONLY` 命令策略；WebSocket 连接使用一次性短期票据，终端详细字节写入独立有界录制文件，SQLite 只保存会话元数据和事件索引。终端不会开放任意本机 Shell、任意地址连接或通过 Host Key 失败回退到 Telnet。
