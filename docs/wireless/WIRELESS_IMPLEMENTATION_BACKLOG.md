# 无线业务实施 Backlog

当前状态：`WIRELESS_IMPLEMENTATION_STATUS=NOT_STARTED`。本轮输出设计和可执行验收场景，不打开无线运行时采集。

## P0：证据与契约冻结

- [ ] 收集受控 H3C AC 型号、软件版本、集群/主备拓扑和脱敏命令输出。
- [ ] 证明 AP 序列号、主 MAC、接口 MAC、AP 组和状态字段的稳定性、时间语义和分页语义。
- [ ] 将 `R/M`、`R/B`、`I` 等原始值与版本证据绑定；未验证前保持 `ASSUMPTION_PENDING_H3C_EVIDENCE`。
- [ ] 把 `tests/wireless_architecture_scenarios.mjs` 扩展成服务端解析器的契约测试。

验收：同一输入重复解析结果一致；身份冲突、Site 冲突、双主和过期观测都有可解释输出。

## P1：增量 Schema 与身份注册

- [ ] 添加 `wireless_ac_binding`、`fit_ap_identity`、`fit_ap_interface_mac`、`wireless_ap_observation`、`wireless_ap_group`、关系表和索引。
- [ ] 迁移脚本具备版本门禁、单事务/可回滚检查和重复执行安全性。
- [ ] 复用 `device_inventory`、现有 Site Scope、审计和凭据引用；不复制密码、Terminal Profile 或 AC 设备主数据。
- [ ] 建立序列号/MAC 的唯一候选和冲突隔离机制。

验收：空库、已有设备库、重复迁移、部分失败恢复和跨 Site 拒绝均通过。

## P2：受控 AC 采集

- [ ] 复用现有 Terminal Profile/凭据安全链路，采集接口不得把秘密写入日志或普通字段。
- [ ] 为每个 AC 生成稳定 `source_revision`，支持重试幂等和原始观测保留。
- [ ] 对未知主机指纹、Telnet 明文风险、连接超时和 AC 部分失败提供明确错误。
- [ ] 先实现只读观测落库，再通过 feature gate 启用状态投影。

验收：模拟 SSH 服务和离线 AC 不会产生伪造 AP 离线；重复采集不重复写入。

## P3：无线 UI 与导航

- [ ] 在设备管理组织树下引用 AC 设备库存，增加 AC 摘要、AP 组、FIT-AP 列表和详情时间线。
- [ ] 实现 Site/AC/组/状态/新鲜度/冲突筛选、分页和部分失败状态。
- [ ] 实现身份确认、替换链和冲突队列的权限/审计交互。
- [ ] 按设备管理主工作区的 1366/1920/2560/125% 视觉基线验收。

验收：只读用户不能写关系；普通设备写权限不能确认身份冲突；所有状态都能追溯来源。

## P4：关系与运维增强

- [ ] 集群/堆叠/主备关系的拓扑视图；多成员保留独立 AC ID。
- [ ] AP 替换、跨 Site 冲突、长期过期、来源修订漂移的运维队列。
- [ ] 状态解析规则版本化、回放、差异报告和安全审计报表。

## 实施前置问题

1. H3C 不同 AC 版本的 AP 状态码是否一致？
2. 主备切换时两个 AC 的输出是否会短时同时呈现主用？窗口如何定义？
3. AP 序列号是否为空、变化或被替换设备复用？
4. 集群/堆叠成员是否共享主 MAC，还是只共享虚拟管理地址？
5. 真实现场是否允许 SSH 优先、Telnet 仅兼容，及其主机指纹确认流程？

在这些问题有证据前，禁止把无线模块标记为已实现或把研究假设当作生产状态。
