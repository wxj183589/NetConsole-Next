# 无线业务导航与 UI 规范

状态：`DESIGN_READY`。设备管理主工作区本轮已落地组织树、Site 视图、分组和筛选；无线 AC/AP 页面仍是后续实现契约。

## 1. 导航层级

```text
设备管理
├─ 全部授权 Site
├─ Site A
│  ├─ 全部设备
│  ├─ AC 设备（引用设备库存）
│  │  ├─ AP 组
│  │  └─ FIT-AP
│  └─ 未分组设备
└─ Site B
   └─ ...
```

无线导航不创建第二个“AC 设备”主列表。AC 节点显示设备库存名称、设备 ID、管理 IP、连接档案状态；点击后进入设备详情或 AC 无线子页面。AP 组只在 AC 下展示，跨 AC 同名组不得合并。

## 2. 设备管理主工作区（已实现的 UI 契约）

- 左侧组织导航：全部授权 Site、全部设备、Site、分组、未分组；支持树内搜索和折叠。
- 右侧库存表：状态、设备名称/ID、管理 IP、厂商/型号、类型、Site/分组、Terminal Profile、最近连通、更新时间、操作。
- 筛选：名称/设备 ID/IP/厂商/类型搜索、厂商、设备类型、分组、状态；查询由服务端分页和 Site Scope 实现。
- 组织树选择只改变查询范围，不绕过服务端权限。跨 Site 批量修改必须在对话框中明确目标，最终由服务端再次检查。
- 空结果、结构异常、无权限/接口不可用都要显示明确状态，禁止用模拟设备填充表格。

## 3. 无线页面契约

### 3.1 AC 摘要

必须展示：设备名称、设备 ID、Site、厂商/型号、管理地址脱敏规则、Terminal Profile 是否已关联、最近观测时间、集群/主备状态、能力来源和错误状态。页面不能展示明文凭据或内部 Credential Reference。

### 3.2 AP 组与 AP 表

表格至少包含：FIT-AP 身份摘要、序列号、主 MAC、当前解析状态、原始状态、来源 AC 数量/名称、AP 组、观测时间、新鲜度、冲突标记。原始状态和解析状态必须同时显示；假设语义要有“待 H3C 证据确认”提示。

筛选必须支持 Site、AC、AP 组、当前状态、新鲜度和冲突状态。默认不隐藏 `CONFLICT`、`UNRESOLVED`、`STALE`，可以用醒目标记和单独筛选，而不是静默丢弃。

### 3.3 AP 详情

详情按时间线显示：身份字段、来源 AC、原始负载引用、状态解析版本、组关系变更、替换链和冲突处理。跨 AC 观测需要明确区分“同一 FIT-AP 的多来源”与“多个无法确认关联的候选”。

## 4. 交互与权限

- 只读用户可以查看其授权 Site 的 AC/AP；无权 Site 在接口层返回拒绝，前端不依赖隐藏菜单防护。
- 有设备写权限但无无线身份管理权限的用户不能确认 AP 冲突、修改替换链或改变 AC 关系。
- 有凭据使用权限才允许从 AC 详情触发受控连接；UI 只显示“已保存/未关联”，不回显密码或 Credential Reference。
- 人工确认身份时必须显示旧值、新值、来源证据、Site、影响范围和确认理由；二次确认后调用幂等接口。
- 禁止“自动信任未知 AP”“一键跨 Site 合并”“按名称相似度合并”。

## 5. 加载与错误状态

| 状态 | UI 表现 |
| --- | --- |
| AC 未配置无线能力 | 显示能力未启用，不伪造空 AP |
| AC 采集失败 | 保留最近观测时间，标记采集失败；不把整站 AP 直接改成离线 |
| AP 观测过期 | 显示 `STALE` 和最后观测时间 |
| 身份冲突 | 显示冲突字段和隔离状态，禁止普通编辑覆盖 |
| 多个当前候选 | 显示 `CONFLICT`，要求选择证据或进入处理队列 |
| 无权 Site | 服务端 403；前端显示无权提示，不泄露资源存在性 |
| 部分 AC 成功 | 显示成功/失败来源分栏，保留每个来源修订号 |

## 6. 响应式与可访问性

设备管理主工作区应在 1366×768、1920×1080、2560×1440 和 Windows 125% 显示缩放下保持：组织树可折叠、表格可横向滚动、关键操作不被遮挡。无线页面沿用相同工作区外壳。所有树节点、筛选、展开/折叠和状态标记需要键盘可达、可读名称和焦点样式；颜色不是唯一状态表达方式。本轮截图验收不等同于完整屏幕阅读器验收。

## 7. 与参考全天猴/SmartHub 页面差异

保留参考页面的工作台信息架构：左侧分组树、顶部工具/筛选、主表、分页、详情入口；但 NetConsole-Next 的差异是：

- Site Scope、服务端分页、权限和审计是实际数据边界，不是前端演示状态；
- AC 复用设备库存，FIT-AP 复用身份注册和观测关系，不复制第三方设备主数据；
- 凭据由后端安全存储管理，页面不展示内部秘密；
- AP 的冲突、陈旧和状态假设显式可见，不通过模糊匹配制造“看似完整”的拓扑。
